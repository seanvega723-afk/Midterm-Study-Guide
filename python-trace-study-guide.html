Start here: Python from zero

If you know nothing yet, read these in order. Each lesson is short, has a small example, and says what Python does and why. Tap a lesson to open it.

The one big idea

A program is a list of instructions. Python is a very literal robot: it reads them from the top, one line at a time, and does exactly what each line says. Your exam job is to be the robot. Go line by line, keep track of what is stored, and write down what gets printed. That is all "tracing" means.

1. Variables: named boxes that hold a value

A variable is a name with a value stored under it, like a labeled box.

x = 10 y = 3

This stores 10 in a box labeled x and 3 in a box labeled y.

The = sign is not "equals". It means "work out the right side, then store the result under the name on the left." The right side always happens first.
x = 5 x = x + 2 print(x)
7

Python computes x + 2 using the current x (5), gets 7, and stores 7 back in x. The old 5 is gone. Storing a new value always replaces the old one.

x = 4 y = x x = 9 print(y)
4

y = x copies the value 4 at that moment. Changing x later does not change y.

2. Kinds of values: numbers, text, True/False
  • Integer (int): a whole number like 5 or -2.
  • String (str): text inside quotes, like 'bye ' or "hello". Quotes can be single or double. Spaces inside the quotes count.
  • Boolean: only True or False. Comparisons produce these.

'5' (with quotes) is text. 5 (no quotes) is a number. They behave differently:

print(5 + 5) print('5' + '5') print('ab' * 3)
10 55 ababab

With numbers, + adds. With strings, + glues them together. A string times a whole number repeats the string.

3. print: the only way to show something on the screen

print(...) displays a value. Each print goes on its own new line. The exam asks "what is the output?", which means: what gets shown by print, in order.

x = 3 print("x") print(x) print(x + 1)
x 3 4

Quotes make text: print("x") shows the letter x. No quotes means "show what is stored in that name": print(x) shows 3. If nothing prints, the output is empty. Calculations without a print never show up.

Candy picture. You have 17 candies and make bags of 5. 17 // 5 is the number of full bags: 3. 17 % 5 is the candies left over: 2. (5 x 3 = 15, and 17 - 15 = 2.)

Small % big: 4 % 9. Nine fits into 4 zero times, so all 4 are left over. The answer is 4.

Even/odd trick: x % 2 is 0 for even numbers and 1 for odd numbers.

Order of operations

Parentheses, then **, then * / // % (left to right), then + - (left to right), then comparisons.

print(2 + 3 * 4) print((2 + 3) * 4) print(10 - 4 - 3) print(10 * 3 % 7)
14 20 3 2

Walk through the last one: * and % tie, so go left to right. 10 * 3 = 30, then 30 % 7 = 2.

5. Comparisons: questions that answer True or False
SymbolAsks
==is it equal?
!=is it NOT equal?
< >less than, greater than
<= >=less than or equal, greater than or equal
One = stores. Two == asks. x = 5 puts 5 in x. x == 5 asks whether x is 5.

Math happens first, the comparison last. 2 + 3 > 4 becomes 5 > 4, which is True. Equal counts for <= and >=: 2 >= 2 is True, but 2 > 2 is False.

6. if / elif / else: making decisions

An if runs its indented lines only when the condition is True. Indentation (the spaces at the start of the line) shows which lines belong inside.

x = 7 if x > 5: print("big") else: print("small") print("done")
big done

7 > 5 is True, so "big" prints and the else is skipped. print("done") is not indented, so it is outside the if and always runs.

elif means "otherwise, if". Python tests top to bottom and runs only the first branch that is True, then skips the rest of the chain.

x = 5 if x > 5: print(1) elif x == 5: print(2) else: print(3)
2
Two separate ifs are different from if/elif. Separate ifs are each checked on their own, so more than one can run (Problem 3 does this). In a chain with elif/else, only one runs.

Nested if: an if inside an if. The inside one is only looked at when the outside one was True (Problem 4).

7. while loops: repeat while something is True

A while loop does this over and over: check the condition. If True, run the indented body, then go back and check again. If False, leave the loop.

i = 0 while i < 3: print(i) i = i + 1
0 1 2

Trace it with a table. One row per check:

  • If the condition is False the very first time, the body runs zero times.
  • If nothing in the body changes the condition, the loop never ends (an infinite loop).
  • "How many times does the loop run?" means how many times the body ran. Check 4 above is not a run.
8. for loops and range()

for i in range(...) repeats for a fixed list of numbers. Python sets i to each number in turn.

CodeNumbers i takes
range(3)0, 1, 2
range(2, 5)2, 3, 4
range(1, 10)1, 2, 3, 4, 5, 6, 7, 8, 9
The start is included. The stop is NOT. range(1, 10) stops before 10. range(3) starts at 0 by default.

break leaves the loop immediately. for ... else: the else runs only if the loop finished without hitting a break (Problem 7).

for i in range(10): if i == 3: break print(i)
0 1 2
9. Functions: defining vs calling

A function is a named block of instructions you can reuse. Think of a recipe card.

def say_hi(): print("hi") say_hi() say_hi()
hi hi
  • def say_hi(): defines the function. It writes the recipe down. Nothing runs yet.
  • say_hi() calls the function. The parentheses mean "do it now". This is cooking from the recipe.
  • Calling it twice runs the body twice.
What "calling a function" really does: Python jumps up to the function's first line, runs the body, then jumps back to the line that made the call and carries on.

If you define a function and never call it, nothing happens. That is why exam programs end with main(): that line starts everything. main is just an ordinary function with a conventional name.

10. Parameters, arguments and default values
def add(a, b): return a + b print(add(2, 3))
5
  • Parameters are the blanks in the def line: a and b.
  • Arguments are the real values you pass in the call: 2 and 3.
  • They are matched in order: a = 2, b = 3.

A default value is used only when you leave that argument out.

def greet(name = "friend"): print("hi " + name) greet() greet("Sam")
hi friend hi Sam

This is the Problem 1 and Problem 5 lesson: f(20) and f(10, 5) pass arguments, so the defaults in def f(x = 20) are ignored.

11. return vs print
  • print shows something on the screen. It does not give a value back.
  • return hands a value back to whoever called the function and ends the function right away. It shows nothing on the screen by itself.
def f(): return 5 x = f() print(x)
5

The call f() becomes the value 5, which is stored in x and then printed. Without a print, nothing would appear. Without x =, the 5 would be thrown away.

def g(): print(5) y = g() print(y)
5 None

g prints 5 but returns nothing. A function with no return gives back None, Python's "no value".

return ends the function. Lines after it never run:

def h(): return 1 print("never") print(h())
1
12. Scope: each function has its own variables

A variable created inside a function is local: it lives only while that function runs. Two functions can each have an x and they do not affect each other.

def change(): x = 99 x = 1 change() print(x)
1

The x inside change is a different box. The only way to get a result out of a function is to return it and store it: x = f(...).

If you write f(x) alone, the returned value is thrown away and x is unchanged. If you write x = f(x), x becomes whatever was returned.
13. Functions calling functions (and recursion)

A function can call another function, or even itself. When f calls something, f pauses on that line and remembers its own variables. The new call runs to the end, then f resumes on the next line. Picture a stack of sticky notes: the newest call is on top and must finish first.

def f(n): if n > 0: print(n) f(n - 1) f(3)
3 2 1

Each call prints first, then calls the next one. f(0) fails the if and does nothing, so everything ends.

Now move the print after the call:

def f(n): if n > 0: f(n - 1) print(n) f(3)
1 2 3

f(3) pauses at f(2) before printing. f(2) pauses at f(1). f(1) calls f(0), which does nothing. Now the pauses unwind from the top: f(1) prints 1, then f(2) prints 2, then f(3) prints 3.

Exam method for Problem 8: write the calls as a growing list (f1(8), f2(6), f1(1), ...). When a call ends, cross it off and go back to the call below it, at the line right after the one it made. Prints placed after a call happen on the way back.

Core rules

Functions & scope

  • A default (def f(x = 20)) is used only when you call f() with no argument. f(20) uses your value.
  • print() shows text and changes nothing. return sends a value back to the caller.
  • Variables inside a function are local. x in f() is not the x in main().
  • x = f(20) overwrites x with the return value. Plain f(20) throws the return value away.

String * int

  • 'ab' * 3 is 'ababab'.
  • s = s * 2 doubles the string every pass: 1, 2, 4, 8, 16 copies.
  • Count hidden spaces. 'bye ' ends with a space, and the space repeats too.

Operator precedence (highest first)

LevelOperatorsNote
1( )Always first

3* / // %Same level, so go left to right
4+ -Same level, left to right

% is the remainder: 30 % 7 = 2 because 7 fits into 30 four times (28) with 2 left. // is division that drops the decimals: 20 // 13 = 1, 10 // 3 = 3.

Six traps to check on every question

Small % big. If the left number is smaller than the right, the answer is the left number. 3 % 7 = 3.
Variable overwrite. Look for x = f(...). With the assignment, the return value replaces x. Without it, x stays as it was.
Loop end-point. i > -1 still runs when i is 0. i > 0 would stop before that pass.
Loop condition that starts false. If the condition is false on the first check, the body runs zero times. Always test the condition before running the body.
for ... else. An else lined up with for runs only if the loop finished without break. Indentation decides which statement an else belongs to.
Print after a call. In recursion, a print placed after a function call waits until that call returns. The deepest call prints first.

The method that works every time

  1. Start at main(). Ignore function bodies until they are called.
  2. Keep a small table of variables. Update it after every assignment.
  3. Evaluate expressions in precedence order and write each intermediate result.
  4. For loops, write one line per pass: condition check, then each body line.
  5. For function calls, note the arguments, run the body, then return to the line that called it.
  6. Write output only when you reach a print.
